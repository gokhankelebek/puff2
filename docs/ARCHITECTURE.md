# Architecture

Next.js **16.3.1** App Router · TypeScript · CSS Modules · React 19.2.8.
Runtime dependencies are `next`, `react`, `react-dom`, `csv-parse`. That is the whole list.

> **This is not the Next.js you know.** `web/AGENTS.md` is regenerated by `next dev`
> and says so: read `web/node_modules/next/dist/docs/` before writing code that
> touches framework surface. Several APIs differ from older App Router versions
> (`headers()` and `searchParams` are async here, for instance).

Redirects live in `next.config.ts`. **Config changes need a dev-server restart** —
HMR will not pick them up, which is exactly how a stale server can serve a route
that no longer exists.

### Slugs are ours

`src/lib/slugs.ts` derives brand slugs from the display name, in one place.
"Geek Bar" → `/vape/brands/geek-bar`. If the POS spelling changes, existing URLs
stay put as long as the name the shop uses does. This is the ownership rule from
[DATA-PIPELINE.md](DATA-PIPELINE.md) made concrete.

`src/middleware.ts` handles the age cookie and sets the `AGE_HEADER` the pages read.

## The commerce adapter is the only seam

`src/lib/commerce/index.ts` exports a single `CommerceAdapter`. **No vendor
vocabulary crosses it.** Nothing in `app/` or `components/` knows Lightspeed
exists; swapping POS means writing one new adapter file and changing one line.

```
catalog.generated.json ──► catalog.ts (pure mapping) ──► CommerceAdapter ──► UI
images.generated.json  ──┘
```

`fixtures.ts` is the offline/test adapter.

### Domain types (`src/lib/commerce/types.ts`)

- **`Department`** — a *browse* decision: `vape · cigars · cigarettes · hookah · glass · accessories`
- **`RegulatoryClass`** — a *legal* decision: `ends · hookah · cigar · cigarette · pouch · rollYourOwn · smokeless · accessory · restricted · unknown`

These are deliberately separate. A hookah bowl and shisha tobacco sit on the same
shelf and in different regulatory buckets. Classification **fails closed** — anything
unrecognised becomes `unknown` and is not publishable.

- **`StockTier`** — `verified · expected · low · unknown · out`. `countedAt` drives the
  provenance line; `remaining` is shown only for `low`, and only when actually known.

## House rules

### 1. Progressive enhancement is not optional

Every primary interaction works before hydration, because on a cold Strip
connection that is most of the time a customer is looking at the page.

| Thing | How |
|---|---|
| Age gate | `<form>` POST to `/api/age` |
| Category facets | plain `<a>` links |
| Search | `<form method="get">` to `/search` |
| Marquee pause | CSS-only checkbox (WCAG 2.2.2) |
| Hotel picker | `<a href="/delivery?hotel=…&tower=…">` — server-rendered, shareable |

If you add an interaction, make the no-JS path the real one and let JS improve it.

### 2. CSS Modules, not Tailwind

Deliberate. Tokens live in `src/app/globals.css`; components own a sibling
`*.module.css`. Never put a raw colour in a component — add a token.

### 3. Theme

`data-theme` on `<html>`, `localStorage`, plus a pre-paint inline script
(`components/InlineScript.tsx`) per Next's `preventing-flash-before-hydration.md`.
`<html>` carries `suppressHydrationWarning`.

### 4. Accessibility floor

WCAG 2.2.2 (pause moving content), 2.5.8 (24×24 targets — 44px on mobile in
practice), 1.4.11 (3:1 non-text contrast), AA 4.5:1 text contrast. All four have
already caught real regressions here; treat them as build criteria, not a later pass.

## Design tokens (`src/app/globals.css`)

> **Stripped for the redesign.** The "Vegas neon" palette described here has been
> removed — see the commit *"Strip the presentation layer, keep structure and
> inventory"*. `git show 3bacdef:web/src/app/globals.css` has the original if you
> need to recover a value.

What survives in `globals.css` is the **contract**, not the design:

| Survives | Why |
|---|---|
| Every token *name* | So nothing in the components dangles while the new system is written |
| The reset, `.mono` / `.micro` / `.srOnly` | `.mono` is load-bearing: a proportional face reflows the clock once a second and fails CLS on its own |
| `data-theme` light/dark + the pre-paint script | The mechanism is orthogonal to the palette |
| The accessibility floor | Focus ring and the `prefers-reduced-motion` budget stay build criteria |

Every colour value is now a neutral placeholder and none of it is a decision.
Removed as art direction: the brand red / volt / hot ramps, the flavour swatch
palette, the humidor `[data-zone]` shift and the late-band `[data-band]` shift.
**The pages still emit `data-zone` and `data-band`**, so both remain available
as hooks if the new design wants them.

All 12 CSS modules are emptied the same way — selectors kept, bodies gone. Each
rule carries an inert `--stripped: 1` declaration, which is not a style: a rule
with an empty body is dropped by the CSS optimizer, and dropping the rule
deletes the class from the module's export map, so `s.tile` comes back
`undefined`. One declaration keeps the export alive.

`NicotineWarning.module.css` is **not** stripped. 21 CFR 1143.3(b)(2)'s
20 %-of-advertisement test makes that component's format a regulatory question,
not a design one — see [COMPLIANCE.md](COMPLIANCE.md).

There is one fenced block at the end of `globals.css` marked
**STRIP ARTIFACT — DELETE WHEN THE NEW DESIGN SIZES THESE**. It gives a fallback
size to three `viewBox`-only SVGs that the stripped modules used to size (the
search magnifier, the grain field, the mall plan); without it the 24px magnifier
lays out at its container's full width. Delete it once the new system sizes them.

Logo assets: `public/brand/logo{,-full,-mark,-mark-sm,-sm}.webp`.

> Watch for non-ASCII homoglyphs in hex values — a Cyrillic `а` in `#8а93a1`
> shipped once. A non-ASCII grep over CSS is a cheap guard.
